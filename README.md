# KunPlayer（B站音乐TV版）

小米电视 4A（Android 6.0.1 / API 23）上自用的 B 站音频客户端。**Kotlin + 传统 View + Media3 ExoPlayer，不用 Compose。**

桌面和系统设置里显示的名字是 **B站音乐TV版**（`@string/app_name`）。KunPlayer 只剩仓库名、包名（`com.kunplayer.tv`）和日志前缀在用，界面上一处都不出现。

> 这是非官方客户端，与哔哩哔哩无关，仅供个人在自有设备上使用。

## 这是什么

B 站没有电视端的「听歌」应用，手机端投屏又要在两个遥控器之间来回切。KunPlayer 把 B 站的音频流、字幕歌词、收藏、关注收进一个遥控器能全程操作的界面：打开电视→选歌→放着别管，或者挑一首细听。

当前版本 **0.30.1**（versionCode 48），全部功能在小米电视 4A 真机验证通过。

## 功能特性

**听**
- 四个曲目来源：音乐推荐流、流行榜、最新发布、推荐音乐（随机长合集，一小时以上）
- 多 P 合集当专辑听：一首歌就是一张专辑，曲目表、计数、切 P 都按 B 站分 P 走
- 正在收听（= 当前播放队列，不是第四个推荐源）、我的收藏、关注、播放历史

**看**
- 播放页右栏三档循环（右下角图标画的是下一档）：歌词 → 列表 → 频谱 → 歌词；没歌词时默认频谱，循环里跳过歌词档。切档时焦点始终留在档位键，按 ↓ 才进列表选歌
- 频谱三种样式（柱状 / 波形 / 环形）在**设置**里换；颜色是一张十色色板（含品牌红与三级中性色），按哪格就是哪格，按下即生效并收起
- 歌词可关、可换色（同一张十色色板）、可换字体（默认 / 黑体 / 宋体）、可换字号（小 / 标准 / 大 / 特大），改完当场在预览行上看到
- 音质五档（自动 / 无损 / 高品质 / 标准 / 流畅）：按码率上限过滤后取最高，该档没有就回落到全局最高；切档不打断正在播的这首，下一首生效
- 列表行：正在播放的那首歌手与时长之间有一颗**小频谱**，只表示「就是这首」
- 底栏：歌手名后滚动显示歌词或宽频谱；歌名按 ↓ 进切换格，确认或左右轮换，按 ↑ 回歌名。没歌词默认频谱，频谱右端伸到「上一首」前，整条居中

**控**
- 冷启动落在「推荐音乐」，先显示上一次换的那一批，不自动重搜；主动按「换一批」或再确认一次才重新抽词
- 头图下方一排**筛选词**（默认 国语 / 粤语 / 纯音乐 / 抖音 / 无损 / 合集 / 演唱会 / 经典 / 精选 / Hi-Res）：按一下就地搜出这一批，标题跟着换成这个词；十个词都能在设置里改，改的是拼音原文
- 侧栏九处去向后，方向键全程可达；列表长按 ↓ 直达底栏，底栏 ↑ 原路返回
- 播放模式（顺序 / 单曲 / 随机）、上一首 / 下一首 / 播放暂停 / 收藏 / 播放模式都真能按
- 搜索：左上角 LOGO 后的放大镜按钮，九宫格键盘 + 弹卡选字母，搜过的词存本地，点一下再搜
- 设置六个二级页：频谱设置 / 歌词设置 / 音质 / 搜索关键词 / 后台播放 / 我的；返回一次只退一层，光标回到进来那一行
- 登录后可切换用户，账号区按当前登录用户显示会员身份（大会员 / 年度大会员 / 会员，或无）

**体验**
- 返回桌面要按两次（2.2 秒内二次确认才退出）
- 后台播放可开关（默认开，关掉则回桌面暂停）
- 响度自动均衡（每首歌测 5 秒长时响度后锁定固定增益，限 0.4~2.5）
- 断点续播（按 `bvid#cid` 记忆进度，冷启动续播）
- 扫码登录（B 站账号），收藏 / 关注 / 观看历史同步云端

## 架构总览

单 Activity（`MainActivity`）承载首页 ⇄ 播放页，浮层（登录 / 搜索 / 收藏夹 / 关注 / 空间）在之上调度。播放器是进程内单例 + 前台服务，界面销毁、回桌面、电视休眠都不影响播放。

```
app/src/main/java/com/kunplayer/tv/
  KunApp.kt                Application：Cookie 落地 + 封面磁盘缓存
  MainActivity.kt          唯一 Activity：页面切换 + 浮层调度 + 按键路由
  ProbeActivity.kt         链路自检页（不占桌面入口）
  audio/AudioTap.kt        自写 AudioProcessor：取 PCM → FFT 频带 / 波形 / 响度均衡
  net/                     B 站接口（WBI 签名、playurl、分区推荐、搜索、收藏、关注、历史、字幕、心跳）
  model/                   接口反序列化模型 + 应用曲目模型（也是缓存落盘格式）
  cache/                   收藏、搜索历史、断点续播、推荐音乐上次结果、设置 的本地存储
  ui/                      首页、播放页、歌词、九宫格键盘、扫码、封面加载、频谱 View
  diag/                    焦点埋点 + 崩溃记录（落文件）
  player/                  ExoPlayer 封装、播放控制单例、前台服务
res/layout/                首页 / 播放页 / 列表行 / 歌词行 / 搜索页 / 各浮层
tools/                     零依赖图标与截图工具、adb 脚本
docs/kunplayer-tv-plan.md  实施计划与完整版本记录
AGENTS.md                  设计 / 文案 / 焦点 / 音频链路 的硬约定（改 UI 前必读）
```

## 设计与关键技术决定

这些决定是后续维护的承重墙，改动前务必理解：

### 频谱来自自写的 AudioProcessor，不是系统 Visualizer

这一路是整条链路里唯一能稳定拿到原始 PCM 的地方。系统的 `Visualizer` 要 `RECORD_AUDIO` 权限、且挂在厂商效果器上，在这台电视（Amlogic T962）上实测靠不住；`LoudnessEnhancer` 只给总响度、拿不到频带。

做法是重写 `DefaultRenderersFactory.buildAudioSink()`，把 `AudioTap` 塞进 `DefaultAudioSink.Builder.setAudioProcessors()`——解码器出来的 PCM 先过它，再进声卡。

**两个坑：**
- 必须同时 `setEnableAudioFloatOutput(false)`。开着浮点输出时 `onConfigure` 收到 FLOAT 编码，分析器会返回 `NOT_SET` 把自己关掉，现象是「频谱装了但一直不动」，不崩溃。
- `queueInput` 输出必须与输入等长（旁路式处理），否则声卡节奏错乱。

FFT 是自写的 1024 点 radix-2（旋转因子与位反转表构造时预算一次）；32 个对数频带（40Hz~16kHz），`-62dB~0dB` 映射到 0~1；渲染侧起快落慢（逼近 0.6 / 衰减 ×0.88）防 30fps 下整排闪。

**三处摆放职责不同，不是同一个 View 到处贴：**
- 播放页右栏：跟真实频带，柱状 / 波形 / 环形 + 十色色板可选，才是「这首歌现在是什么样」
- 列表行：5 根正弦相位假动柱子，**只回答「就是这首」**，不接音频（跟着音乐跳会在一列静止歌词里抢注意力）
- 底栏 14dp 高的宽条：**只画柱状**——环形塞进去只剩一个色点、波形摊在一条扁带里是一道糊

### 歌词来自 B 站 CC 字幕，不是另一个歌词库

```
x/player/wbi/v2?bvid&cid    → data.subtitle.subtitles[]   （WBI 签名 + 登录）
取中文那条的 subtitle_url   → 公开 CDN，裸 GET，不带 Cookie
body[{from, content}]       → from 是秒（两位小数）
```

- **必须登录**：匿名请求 `code=0` 但 `subtitles` 是空数组（谎报的空列表）。未登录干脆不请求。
- **字幕 URL 约 30 秒有效**（`auth_key` 首段是过期时间戳）。只缓存解析后的文本，URL 不留。
- **cid 必须是正片 cid**（多 P 合集用顶层 cid，和 playurl 是同一个坑）。
- 字幕是整段语音识别，B 站用 ♪ 包住「唱的那几行」作为唯一过滤依据；三道闸门：♪、条数（<8 不算）、行距（<500ms/行不算）。AI 对纯音乐专辑「听」出的假歌词区分不出来，已知问题，接受。
- 覆盖率不乐观（音乐区推荐流 73%、流行榜 40%），所以这条链路是「有就显示」，拿不到只写一行「暂无歌词 / B 站没有为这首歌提供字幕」。

### 合集：多 P 稿件就是一张专辑

音乐区里「一张专辑」最常见的形态是一个 100 P 稿件。列表接口把它压成**一条**记录只带 P1 的 cid；`x/web-interface/view?bvid=` 一次给全所有 P（`pages[]`），100 P 响应约 8KB。

三个容易踩的地方：
- 取流缓存键从 bvid 换成 **cid**（100 首共用一个 bvid，按 bvid 命中会一直拿到 P1）
- 正在播标记按 **cid** 判，不能按 bvid（否则合集那 100 行整列亮红条）
- 起播后队列换成整张专辑，但**不重新取流**（重新取流会把播放头拨回 0）

断点续播的键也是 **`bvid#cid`**——理由同上，合集 100 P 共用一个 bvid。

### 推荐内容过滤

音乐区推荐流是混合内容，必须过滤才听得下去：时长闸门 30s~20min；关键词闸门只挡最明确的几类（开箱 / 乐评 / 盘点 / 教学 / 饭拍 / 直播回放 / reaction / 解读 + 新闻类）；「翻唱 / 演奏 / MV / Live」这些既可能是歌也可能是噪音的词一个都不挡。少一条新闻比多十条歌重要。

### 导航模型：首页移动，播放页动作

首页方向键是**移动**（交给 FocusFinder），播放页方向键是**动作**（由 `dispatchKeyEvent` 直接映射）——播放页没有可去的地方。

底栏光标可达性：列表里**长按 ↓ 直达底栏**（约 0.9 秒，单击仍一行一行走），侧栏末项 ↓ 也到底栏，到底栏后 ↑ 按原路返回（从列表下来回原行，从侧栏下来回侧栏）。落点是播放键而非歌名——歌名是这排里最不显眼的一颗，焦点停在那儿整排方盒一颗不亮，用户会以为还停在列表。

焦点规则以 `HomeStage.handleKey` 手工分发为准，**不要退回 `nextFocusDown`**；`android:selected` 不是合法 layout 属性，跑马灯只能在代码里 `isSelected = true`。

### 播放页（`overlay_now.xml`）

| 区域 | 内容 |
|---|---|
| 左栏 | 封面卡 → 歌名（19sp，右侧大爱心）+ 歌手（可聚焦进主页）→ 进度条 → 时间 → 控制行 |

## 构建

需要 **JDK 17** 与 **Android SDK**（platform 35 + build-tools 35.0.0）。本机的 JDK / SDK 解压在 `C:\Users\Kun\toolchain` 与 `C:\Users\Kun\android-sdk`，不污染 PATH：

```bash
export JAVA_HOME="C:\Users\Kun\toolchain\jdk-17.0.2"
export ANDROID_HOME="C:\Users\Kun\android-sdk"
./gradlew :app:assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`。

release 签名读根目录的 `keystore.properties`（口令）与 `keystore/kunplayer-release.jks`。两个都在 `.gitignore` 里——**jks 丢了就再也盖不上已装的包，只能卸载重装**，务必单独备份。缺配置时构建不会失败，会回落到 debug 签名并在日志报警告。

## 安装到电视

电视开启 ADB 调试后：

```bash
adb connect <电视IP>:5555
adb install -r app/build/outputs/apk/release/app-release.apk
```

`-r` 覆盖安装要求签名一致；换了 keystore 只能 `pm uninstall` 重装，数据（登录态、收藏、队列模式）需先用 `run-as` 搬过去，步骤见 `docs/kunplayer-tv-plan.md`。U 盘装也行（原厂桌面删了之后走文件管理器）。桌面图标两条 intent-filter 都声明了，第三方桌面都能扫到。

## 取诊断数据

自用包刻意保留 `debuggable`：

```bash
adb exec-out run-as com.kunplayer.tv cat files/diag.log        # 焦点埋点
adb exec-out run-as com.kunplayer.tv cat files/crashes/*.log   # 崩溃记录
```

日志按 32 条一批落盘，回桌面（`onStop`）时把尾巴写掉。上架前必须关掉 `debuggable`。

## 约定（AGENTS.md）

视觉、文案、焦点、音频链路的硬约定全部写在仓库根 `AGENTS.md`，改 UI 前必读，要点：

- **避免不必要的辅助标签和描述，让布局自己说话**（英文原句 `Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.` 照抄不改）。删掉一段字，用户还能从标题/分组/间距/选中态拿到同样信息就删。
- **冗余 UI 一律删**，布局读不清就重构结构，不靠加 padding / 分隔线打补丁；删控件前先 grep id（焦点主要靠 `handleKey` 手工分发）。
- **迭代兼顾用户 / 开发 / AI Agent 三者体验，且不破坏现有功能**：老路径按键数不变、同一能力只有一处真源、规则写进仓库而不是对话里；改完构建 + 装真机逐条回归。
